# Voice System Architecture

Airi includes a complete, low-latency Voice Pipeline designed for natural conversational interactions.

## Architecture Pipeline

```text
Microphone -> Wake Word Engine -> STT (Speech-to-Text) -> AI Provider -> TTS (Text-to-Speech) -> Speaker
```

## Components

### 1. Wake Word (openWakeWord)
Continuously listens to the microphone buffer for the designated wake word (e.g., "Hey Airi"). This runs purely locally and is highly optimized for low CPU usage.

### 2. Speech-to-Text (faster-whisper)
Upon wake word activation, audio is recorded until silence is detected, then processed by `faster-whisper`. This provides near real-time, highly accurate transcription using local compute.

### 3. Text-to-Speech (Kokoro)
Responses generated by the AI Provider are synthesized into natural-sounding speech using the Kokoro TTS engine.

## Audio Pipeline

The system uses `asyncio` queues to stream audio chunks between components.
- The microphone stream is non-blocking.
- TTS generation can begin streaming audio to the speakers before the entire sentence is generated (if the AI provider supports token streaming).

## Push-to-Talk Fallback

For noisy environments, or if you prefer not to have an always-on microphone, Airi supports a Push-to-Talk mode which bypasses the Wake Word engine entirely.

## Adding a New STT/TTS Provider

The voice system uses abstract interfaces: `STTEngine` and `TTSEngine`. You can easily add support for cloud providers (like ElevenLabs for TTS) by implementing these interfaces and registering them in the configuration.

## Voice Configuration

Adjust settings in `.env`:
```env
VOICE_ENABLED=true
WAKE_WORD_SENSITIVITY=0.5
STT_MODEL=tiny.en
TTS_VOICE=default_female
```
